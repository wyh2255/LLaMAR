ContextManager 三层记忆系统

Pinned State + Episodic Memory + Recent Window — 架构文档 · 2026-07-04

1. 概述

ContextManager 位于 src/Agent/router_agent/context.py 和 src/Agent/worker_agent/context.py，提供 三层递进记忆模型，在每次 LLM 调用前组装 memory block 注入 system prompt。

系统采用 Pinned State + Episodic Memory + Recent Window 三层架构，实现高效上下文管理：

System Prompt
Environment Layer — 宏观场景信息（fires / persons / agents）
Current State Layer — 自身状态（position / inventory / step）
Action History Layer — 最近 N 步操作记录（episode summaries）
Context Memory (assembled by ContextManager)
Raw Messages — 最近 K 条 assistant/tool 消息

2. ContextConfig

2.1 配置数据类

ContextConfig 是一个 dataclass，控制 ContextManager 的全局行为策略：

@dataclass
class ContextConfig:
    strategy: str = "hybrid"
    # "none"     — 不 prune，但 observe() 正常执行（pinned + episodic 仍然更新）
    # "summary"  — 只做 episodic summary，pinned 提取受 `pinned_enabled` 控制（与 hybrid 行为相同）
    # "hybrid"   — pinned + episodic + recent window（默认）
    # "raw"      — 透传模式：跳过 observe/prune/assemble 全部处理
    state_mode: str = "semantic"         # "semantic" | "oracle" — 决定 pinned state 的 Environment 层渲染策略（仅 router 副本支持）
    recent_messages: int = 12            # 保留最近 N 条 assistant/tool 消息
    summary_trigger_ratio: float = 0.8   # token_limit 的 80% 触发 summary
    pinned_enabled: bool = True          # 是否启用 pinned state 提取
    episodic_max_items: int = 20         # episodic 最大条目数
注意：Worker 端的 ContextConfig（src/Agent/worker_agent/context.py:36）同样有 state_mode: str = "semantic" 字段。state_mode 在两端的 ContextConfig 中均存在。

3. ContextManager 基类

3.1 数据结构

class ContextManager:
    pinned: dict[str, Any]                    # 旧式 dict pinned state（向后兼容）
    _pinned_state: BaseModel | None            # 新式 typed pinned state
    episodic: list[_Episode]                   # 总结化的历史操作
    _task_snapshots: dict[str, tuple[list[Message], dict | None]]  # 内存 snapshot
    _log_dir: Path | None                      # 磁盘 snapshot 目录

3.2 observe() — 工具结果处理

每次 Agent 执行完工具后调用，负责更新 pinned state 与 episodic 记忆：

def observe(self, tool_name: str, content: str, success: bool, state_mode: str | None = None):
    if self.config.strategy == "raw":
        return

    if state_mode is not None and self._pinned_state is not None:
        if hasattr(self._pinned_state, "state_mode"):
            setattr(self._pinned_state, "state_mode", state_mode)

    if self.config.pinned_enabled:
        extracted = self._extract_pinned(tool_name, content, success)
        if extracted:
            self.pinned.update(extracted)
            if self._pinned_state is not None:
                for k, v in extracted.items():
                    if hasattr(self._pinned_state, k):
                        setattr(self._pinned_state, k, v)

    status = "success" if success else "failure"
    truncated = content[:500] + "..." if len(content) > 500 else content
    self._episode_counter += 1
    self.episodic.append(_Episode(
        step=self._episode_counter,
        tool_name=tool_name,
        summary=f"{tool_name} → {status}: {truncated}",
    ))
    self._prune_episodic()
关键行为：若 strategy == "raw"，observe() 立即返回，跳过所有处理。content 超过 500 字符时会自动截断。

3.3 prune_history() — 消息剪枝

从 message list 中移除较早的 assistant/tool 消息，被移除的 assistant 消息自动转为 episodic 条目：

recent = self.config.recent_messages
exec_indices = [i for i, m in enumerate(messages)
                if m.role in ("assistant", "tool") and i > 0]
if len(exec_indices) <= recent:
    return

to_remove = set(exec_indices[:-recent])
# Fix: 移除被剪枝 assistant 的后缀孤儿 tool 消息
remaining_exec = [i for i in exec_indices if i not in to_remove]
found_assistant = False
for i in remaining_exec:
    msg = messages[i]
    if msg.role == "assistant":
        found_assistant = True
    elif msg.role == "tool" and not found_assistant:
        to_remove.add(i)
# 被移除的 assistant 消息 → 追加到 episodic
for i in sorted(to_remove):
    msg = messages[i]
    if msg.role == "tool":
        continue  # 已在 observe 中记录
    if msg.role == "assistant" and msg.content:
        self._episode_counter += 1
        self.episodic.append(_Episode(...))

messages[:] = [msg for i, msg in enumerate(messages)
               if i not in to_remove]
self._prune_episodic()
注意：剪枝逻辑会处理"孤儿 tool 消息"——当某个 assistant 消息被移除后，其后续的 tool 消息如果没有前置 assistant 配对，也会被一起移除。

3.4 assemble() — 最终消息组装

def assemble(self, system_prompt, messages):
    if self.config.strategy == "raw":
        return [Message(role="system", content=system_prompt)] + messages[1:]  # 透传

    result = [Message(role="system", content=system_prompt)]
    result.extend(messages[1:])               # 原始消息优先（DeepSeek prefix caching）
    memory_text = self._render_memory_block() # 三层 memory block
    if memory_text:
        result.append(Message(role="user", content=memory_text))  # memory block 在末尾
    return result
设计要点：原始消息优先排列以利用 DeepSeek prefix caching，memory block 作为 user 消息附加在末尾。透传模式下仅保留 system + raw messages，跳过所有 memory block 组装。

4. 三层 Memory Block 渲染

4.1 _render_memory_block()

def _render_memory_block(self) -> str:
    lines: list[str] = ["---", "## Context Memory", "---"]
    env_text = self._render_environment_view()
    if env_text:
        lines.append("### Environment")
        lines.append(env_text)
        lines.append("---")
    state_text = self._render_current_state()
    if state_text:
        lines.append("### Current State")
        lines.append(state_text)
        lines.append("---")
    if self.episodic:
        lines.append(f"### Action History (last {len(self.episodic)} steps)")
        for ep in self.episodic[-10:]:
            lines.append(f"- step {ep.step}: {ep.summary}")
        lines.append("---")
    return "\n".join(lines)

4.2 可覆写方法

父类定义两个空方法，子类覆写以提供领域特定内容：

def _render_environment_view(self) -> str:   # 环境层 → 场景宏观信息
    return ""

def _render_current_state(self) -> str:       # 状态层 → 自身位置/库存/步数
    if not self._pinned_state:
        if self.config.pinned_enabled and self.pinned:
            return "\n".join(f"- {k}: {v}" for k, v in self.pinned.items()
                             if v is not None)
    return ""
覆写模式：子类通过覆写 _render_environment_view() 和 _render_current_state() 注入领域特定的环境与状态信息。_render_current_state() 的默认实现回退到 self.pinned dict 输出。

5.3 双写策略

系统采用 双写策略 确保向后兼容与类型安全：

_extract_pinned() → dict
    → self.pinned.update(extracted)          # dict 写入（向后兼容）
    → self._pinned_state 逐个字段 setattr    # BaseModel 写入（类型安全）

双写优势：

  • self.pinned（dict）继续保持向后兼容
  • self._pinned_state（BaseModel）提供类型安全和结构化访问
  • snapshot 持久化优先使用 _pinned_state.model_dump()

6. Snapshot 持久化

6.1 保存

def save_snapshot(self, task_id, messages):
    pinned_data = self._snapshot_pinned_data()
    self._task_snapshots[task_id] = (copy.deepcopy(messages), pinned_data)
    path = self._snapshot_path(task_id)
    if path is not None:
        try:
            os.makedirs(path.parent, exist_ok=True)
            payload = {
                "pinned": pinned_data,
                "messages": [m.model_dump() for m in messages],
            }
            with open(path, "w", encoding="utf-8") as f:
                json.dump(payload, f, ensure_ascii=False, indent=2)
        except OSError:
            pass
优先级：_snapshot_pinned_data() 的返回值优先级为：_pinned_state.model_dump() > dict(self.pinned) > None。

6.2 加载

def load_snapshot(self, task_id):
    # ① 优先查内存
    if task_id in self._task_snapshots:
        msgs, pinned_data = self._task_snapshots.pop(task_id)
        self._restore_pinned_data(pinned_data)
        return msgs
    # ② 回退到磁盘
    path = self._snapshot_path(task_id)
    if path is not None and path.exists():
        try:
            with open(path, "r", encoding="utf-8") as f:
                payload = json.load(f)
            os.remove(path)
            if isinstance(payload, dict) and "messages" in payload:
                self._restore_pinned_data(payload.get("pinned"))
                return [Message.model_validate(m) for m in payload["messages"]]
            # 兼容旧格式：payload 本身是 message list
            return [Message.model_validate(m) for m in payload]
        except (OSError, json.JSONDecodeError):
            pass
    return None
加载策略：优先查询内存缓存（_task_snapshots），回退到磁盘 JSON 文件。支持新格式（{pinned, messages}）和旧格式（message list）。加载后自动删除磁盘文件（一次性消费）。

6.3 路径规则

{log_dir}/snapshot_{task_id}.json

8. 与 AgentController 的集成

ContextManager 通过 观察者模式 集成到 AgentController 的执行管线中：

AgentController.submit()
    → session_factory() → ContextManager 实例
        → agent.attach_context(ctx)          # 注入观察钩子
            → agent.run()
                → post_tool() → ctx.observe(tool_name, result, success)
                → pre_llm() → ctx.prune_history(messages)
                → ctx.assemble(prompt, messages) → LLM

8.1 构建链中的 log_dir 传递

log_dir 参数通过构建链逐级传递到 ContextManager：

RouterBuildOptions.log_dir  ─→  build_router_agent()
    └→ Agent(log_dir=...)   ─→  AgentController 内部创建 ContextManager
RouterControllerBuildOptions  ─→  build_router_controller()
    └→ session_factory()    ─→  CoordinatorContextManager(..., log_dir)
