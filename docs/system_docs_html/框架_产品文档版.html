LLaMAR 系统框架

多智能体协同系统 — 架构文档 · 2026-07-04

1. 系统概述

LLaMAR（Long-Horizon Planning for Multi-Agent Robots）是一个多智能体协同系统，采用 Coordinator-Worker（协调器-工作者）主从架构，基于 Google A2A (Agent-to-Agent) 协议实现智能体间通信。

系统代码位于 src/ 和 sar_orch/ 两大目录，Agent 框架位于 src/Agent/，使用自定义 ReAct 引擎。所有组件共享同一套 src/a2a/ 传输层、sar_orch/ SAR 实验编排和 SAR 领域工具。

3. A2A 传输层 (src/a2a/)

3.1 架构概览

A2A 层提供 Coordinator-Worker 通信基础设施。项目的 src/a2a/ 通过命名空间包合并与 site-packages/a2a/ (a2a-sdk) 组合。

3.2 双通道通信

通道端口协议用途
WebSocket8080JSON注册、心跳、任务中继、取消
A2A HTTP8081 / 8090Protobuf JSON-RPC任务下发、流式响应、AgentCard 发现

注册流程：

  1. Worker 启动 A2A HTTP 服务器（端口 8090）
  2. Worker 通过 WebSocket 连接 Coordinator（端口 8080）
  3. Coordinator 从 /.well-known/agent-card.json 拉取 AgentCard
  4. Coordinator 注册 Worker 能力/后端/模型

4.3 Agent.run() 核心循环

步进循环 (max_steps)：

  1. 安全检查点（取消/继续？）
  2. Token 预算检查 → 必要时压缩历史
  3. Hook: pre_llm() → 组装上下文记忆
  4. LLM.generate(messages, tools)
  5. 累计 token 使用量
  6. Hook: post_llm()
  7. step_callback("llm_response")
  8. 若 LLM 无工具调用 → 退出
  9. 遍历 tool_calls：
    1. step_callback("tool_start")
    2. Hook: pre_tool()
    3. tool.execute(**args)
    4. Hook: post_tool() → 更新 pinned 状态
    5. step_callback("tool_result")
    6. 检查 task_complete 标志

4.4 上下文管理

三层记忆模型：

层级内容限制
Pinned 状态结构化键值事实（位置、库存、已知火灾等）每次工具执行后更新
Episodic 记忆压缩后的历史工具片段最多 20 条
Recent 窗口原始 assistant/tool 消息最近 12 条

4.5 Controller 编排层 (src/Agent/controller/)

AgentController 是前端无关的编排器：

  • 管理会话（context_id → ContextManager 映射）
  • 并发控制（每个 context_id 一把 asyncio.Lock）
  • 通过 agent_factory 回调创建 Agent
  • 输出通道：EventSink 协议（llm_response / tool_start / tool_result）

5.3 SARBarrier 线程模型

原语用途
threading.Event（按 agent）跨线程唤醒信号
threading.Lock防止 _execute_step() 并发执行
STEP_TIMEOUT = 60s超时自动填充 NoOp

步进生命周期：

  1. Worker 调用 submit_action(idx, action) → 存储动作
  2. 全部提交 → 调度 _execute_step()
  3. env.step(actions) → 生成观测 → 设置所有 Events → Worker 唤醒
  4. 超时：60s 后自动填充 NoOp

9. 关键设计决策

决策原因
router_agent/ 和 worker_agent/ 代码重复允许各自独立演化（worker 支持 NeedInputError，router 不需要）
Barrier 使用 threading 而非 asyncio 原语Worker 运行在不同线程的独立 asyncio 事件循环中
.env 字段必须小写框架统一读取逻辑
step_callback 作为唯一输出通道解耦 Agent 内核与前端（A2A / CLI / 实验）
get_agent_state 不消耗步数零成本 GPS 查询，避免 LLM 因位置感知而浪费步数
NavigateTo 是瞬移SAR GridEngine 直接 set_position()，无需路径规划
增量写入 summary.csv进程崩溃时保留最新数据
