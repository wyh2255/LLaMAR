Sandbox Policy

沙箱策略 — 设计、配置与行为说明 · 2026-07-04

1. 系统概述

Sandbox Policy（沙箱策略）是 LLaMAR 系统中用于限制智能体文件系统访问并禁用 Bash 执行的安全机制。它适用于所有 A2A 智能体工具——包括 workers、coordinator（router）和 verifier——通过 SandboxedTool 包装工具，拦截 read_file / write_file / edit_file 以及 bash / bash_output / bash_kill 调用。

2. Profiles

通过 --sandbox-profile 参数可选择两种沙箱 Profile：

off 默认（独立 CLI 模式）

  • SandboxPolicy.off() — 无任何限制
  • 所有 check_read / check_write / check_tool_import_dir 校验均通过
  • Bash 不受策略阻止（SandboxedTool 在 _enabled 为 False 时透传）
  • 适用于本地调试和开发

workspace 默认（SAR 实验模式）

  • SandboxPolicy.workspace() — 路径受限、Bash 禁用
  • 所有文件路径均相对于 workspace 目录解析
  • 仅允许在 read roots、write roots 和 tool import roots 范围内的路径
  • Bash 默认禁用（bash_enabled=False，但可通过参数覆盖）

2.1 Allowed SAR Write Paths

SAR 实验配置了显式的写根目录：

Write Root内容
<experiment_log_dir>/结果 CSV（轨迹、智能体交互、Token 使用量、汇总）
注意：sar_orch/experiment.py:198-205 显式传递 write_roots=[_result_dir]，因此在 SAR 模式下仅实验日志目录为写根目录 — ./workspace/ 不是 允许的写路径。

<experiment_log_dir> 是由 ExperimentLogger 自动生成的时间戳目录（如 sar_orch/results/sar_experiment_20260704_120000/）。

2.2 Allowed Read Paths

默认仅允许读取 workspace 目录。任何读取 ./workspace/ 之外的文件（包括系统文件、项目源码等）均被拒绝。

2.3 Tool Import Allowlist

工具导入根目录默认为项目根目录（仓库根）。项目内的工具目录（如 sar_orch/tools/）被接受；项目树之外的目录被拒绝。

2.4 Escape Prevention

沙箱实现了三种逃逸防护机制：

.. 路径组件

包含 .. 的路径将触发 SandboxViolation("Escape attempt") 异常。

Symlink 解析

通过 Path.resolve() 检测解析到允许根目录之外的符号链接。

绝对路径限制

允许根目录之外的绝对路径始终被拒绝。

3. Non‑goals

Sandbox Policy 不涉及以下领域的隔离：

✗ 网络沙箱

智能体可发起出站 HTTP/WebSocket 连接，不做限制。

✗ 内存沙箱

智能体共享 Python 进程堆空间。

✗ 子进程沙箱

Python 子进程继承父进程的沙箱策略（或无沙箱）。

✗ OS 级隔离

无 seccomp、AppArmor 或容器边界。
