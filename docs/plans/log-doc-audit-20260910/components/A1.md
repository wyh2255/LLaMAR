1. **[中-高] subtasks.csv 终态行语义缺失**（partial）：logging_map §5a / AGENTS.md:179 / experiment_design:408 都写 finish_task 补 mission 级 completed/failed 终态行，但**该行依赖 Coordinator 主动调 finish_task 工具**；实测 success 收官 run（seed_20，EndReason=success，26 步）router_interactions 无任何 finish_task 调用（barrier checker 判定完成），subtasks.csv 只有 assigned×5/canceled×5，无 mission 行。AGENTS.md "running" 状态无调用点（代码仅 4 处 log_subtask：assigned/canceled/completed/failed）。proposer_log_guide:295 甚至把 "finished=true 仍无 mission 行" 定义为调度缺陷信号——按此口径 seed_20 就是缺陷，但更可能是文档假设（coordinator 必自报完成）与真实收官路径（barrier checker）不符。证据：coordinator.py:470-476、seed_20/subtasks.csv、seed_20/router_interactions.csv。
2. **[中-高] run_metrics.json 新增段无字段清单**（partial）：logging_map §6 只列 10 个基础字段，实际 final_metrics 含 `memory_terminal`（materialized/scope_id/acceptance{failed_tool_rows,missing_error_code_rows,framework_error_counts}/acceptance_gate/projection_quality/truth_recorder）与 `long_term_reflection`（status/drain/diagnosis/quality/source_traceability_rate/forbidden_truth_violation_count 等），experiment.py:1211-1232 追加。两个 run 均有此段（seed_0 diagnosis.status=timeout；seed_20 diagnosis=null）。文档无字段含义 → 使用者无法解读 acceptance_gate 等关键评测字段。证据：experiment.py:1204-1232、两个 run_metrics.json。
