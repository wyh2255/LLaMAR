## 2. truth 目录 run_name 碰撞——根因专节

### 2.1 机制（代码路径）

1. **run_name 推导**：`experiment.py:682` `truth_out = Path(_RESULTS_ROOT) / "truth" / exp_dir.name`——truth 目录名直接取 **log_dir 的 basename**（`exp_dir.name`）。
   - 单跑（不传 `--log-dir`）：`experiment.py:634-637` 自动生成 `{YYYYMMDD_HHMMSS}_s{scene}_s{seed}_a{agents}`，basename 含时间戳 → 唯一，无碰撞（正常样本 `20260909_232036_s3_s42_a4` 等证实）。
   - driver 显式传 `--log-dir`：`run_baseline_s3.sh:19,27` 传 `${BASE}/agents_${agents}/seed_${seed}` → basename=`seed_N` → **同一 seed 跨 agents 全部碰撞**。
   - benchmark 模式：`benchmark.py:208-215,289,304` 传 `scene_S/agents_A/seed_N` → basename=`seed_N` → **scene×agents×seed 全碰撞到 seed_N**（W1 起 truth 默认开启，任何 benchmark 跑必踩）。
   - G3 矩阵（`run_g3_read_matrix.sh:14`）：basename=`scene_{S}_agents_{A}` 唯一 → 不碰撞。
2. **写盘无隔离**：`truth_recorder.py:200-206` `open(trace_path, "a")` 追加、无锁、**claim 不含 run_id**；`finalize()`（:414-437）覆盖写 manifest。
   - lane A/B 并发跑同一 seed 的不同 agents（run_baseline_s3.sh:50-53）→ 两个进程同时 append 同一文件。
   - resume 补跑（run_baseline_s3_resume.sh）→ 同一 combo 多次跑，全部追加同一 trace。
3. **manifest 语义漂移**：manifest 由「最后 finalize 的 run」覆盖写，`truth_trace_sha256` 对**混合后整个 trace 文件**计算。

### 2.2 碰撞现场证据（sar_orch/results/truth/seed_0/）

| 证据 | 数据 | 说明 |
|------|------|------|
| 多 run 指向同一目录 | agents_{2,3,4,5}/seed_0 的 metadata.json `truth_dir` 全部 = `.../truth/seed_0/` | 4 个 run 共享 |
| trace 多 run 混合 | step 回跳（前值>当前值）36 次；正常样本 `20260909_232036_s3_s42_a4` 为 0 次 | 混合体（含 resume 重跑段） |
| manifest 最后者胜 | run_id=sar-scene3-agents5-seed0-099a58c3（agents=5），trace mtime 01:26 早于 manifest mtime 05:39 | agents_5 重跑 finalize 覆盖，自身 steps=0 无新 claims |
| 评测输入漂移 | agents_2 quality `truth_trace_sha256`=59d99c89… ≠ 最终 manifest b03facce…；agents_4 quality `scope_id`=a93adfa9… ≠ manifest scope b1caccc5… | 各 run 完成时点不同 → 评测读到的 trace 是「当时已混合」的不同快照 |
| 空 trace 样本 | seed_40 truth_trace.jsonl 0 字节 + manifest sha=e3b0c442…（空文件哈希）；agents_2/seed_40 为 framework_error、steps=0、elapsed 18s | steps=0 run 仍 finalize（truth_recorder.py:419-421 touch） |

### 2.3 影响面

1. **评测可信度**：`memory_projection_quality.py` 以 manifest（scope_id + trace 路径）为输入做 post-hoc 比对——碰撞后 trace 是多个 scope 的 claims 混合体，`worker_report_quality` 分母（observable 数）被放大、`memory_integration_quality` 的投影比对跨 run 错配；scope 不匹配场景下评测器仍按 measured 输出（实测 agents_4 scope a93adfa9 vs manifest b1caccc5 时 metric_status=measured）。**baseline-20 的 5 个 seed 全部受影响**（seed_0/10/20/30 混合、seed_40 空）。
2. **并发写**：无锁 append，进程级交错风险（本轮实测未见坏行，但属竞态窗口内侥幸；JSONL 行长度不一，写放大时可能半行）。
3. **归因丢失**：trace claim 无 run_id，混合后无法回溯到具体 run。
4. **文档层面**：AGENTS.md:142 gotcha 的方向性误导（见 #15）。

### 2.4 文档是否预警

**否**。三份对照文档（AGENTS.md:25/154、logging_map.md:33/183-187、memory.md:642-647）均只记载：
- 默认路径 `sar_orch/results/truth/<run_name>/`
- 必须位于 run results 之外（experiment.py:680-690 校验）
- metadata.json 记录 truth_dir
- evaluator-private、默认开启、manifest 含 sha256

未记载：run_name = log_dir basename 的推导规则；basename 重复时无任何保护；并发/重试场景的碰撞风险；steps=0 空 trace 行为。唯一相关的 gotcha（AGENTS.md:142）反而建议显式 log_dir，与实际碰撞机制冲突。

## 4. 初步修复建议（不实施，仅供编排侧决策）

1. **（P0，代码）truth 目录名弃用 basename，改用 run 级唯一标识**：如 `<run_id>` 或 `s{scene}_a{agents}_seed{seed}_{run_id[:8]}`（experiment.py:668 run_id 已含 scene/agents/seed/uuid8）。最低成本方案：`truth_out = _RESULTS_ROOT / "truth" / f"{exp_dir.name}_{run_id}"`，与现有唯一 run 目录一一对应。
2. **（P0，代码）TruthRecorder 加碰撞防护**：`__init__` 时若目标目录已存在且 manifest.run_id != 当前 run_id（或 trace 非空），fail-fast 换唯一名或报错——把「静默混合」变成「显式拒绝」。
3. **（P1，代码）trace 行加 run_id 字段**（向后兼容：manifest 加 `trace_run_id` 或直接进 claim），或每 run 独立子目录；manifest 记录 trace 实际包含的 run_id 集合。
4. **（P1，文档）AGENTS.md truth 行补全**：run_name 推导规则、唯一性约束、并发/重试碰撞警告；修正/补充 :142 gotcha（区分 run 目录与 truth 目录两套命名）。
5. **（P1，文档）logging_map.md benchmark 表补 `seed_N_pass_N`**；experiment_design.md §3.4 补 benchmark 模式下 truth 落点说明。
6. **（P1，文档+校验）validate_run.py 收录进官方文档**（AGENTS.md 或 logging_map），L2 truth_dir 检查增强：校验 manifest.run_id == metadata.run_id，不匹配即 FAIL（可拦截碰撞污染后的假 PASS）。
7. **（P2，文档）driver 产物一句话标注**：run_baseline_s3.sh / run_g3_read_matrix.sh 的 LAUNCH_INFO、driver.log、baseline_summary.tsv 属框架外 driver 产物，在 AGENTS.md 或 logging_map 提交集处加一行「见 A1/A2/A3 审计」指路；顺带说明 steps=0 run 的空 trace 属设计内行为（truth_recorder.py:419-421 touch）。
8. **（P2，数据）存量污染处理**：baseline-20 的 truth 评测结论需标注「truth 输入受碰撞污染」，重跑相关评测时用 `--truth-trace` 显式指向单 run 快照（无现成快照，需接受现状或重跑）。
