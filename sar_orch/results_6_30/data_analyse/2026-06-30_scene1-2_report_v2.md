## 4. Scene 1 vs Scene 2 系统对比

| 指标 | Scene 1 | Scene 2 | 差异 |
|------|---------|---------|------|
| 总成功率 | **90%** (18/20) | **55%** (11/20) | Scene 2 失败率高 3.5 倍 |
| 最佳 agent 配置 | a2/a3/a5: 100% | a5: 100% | Scene 2 可选配置狭窄 |
| 最差 agent 配置 | a4: 60% | a4: 20% | Scene 2 a4 几乎不可用 |
| 成功平均步数 | 22.6 | 20.7 | 接近 |
| 失败平均步数 | 60.0 | 60.2 | 一致（都耗尽了步数） |
| 失败平均 transport | 0.73 | 0.74 | 接近 |
| 成功平均 Token | 967K | 395K | Scene 2 更省 token |
| 失败平均 Token | 2572K | 1216K | Scene 2 失败消耗也更少 |

**核心洞察：**
- Scene 2 的低成功率不是因为 agent "死得更惨"（transport rate 和步数与 Scene 1 失败类似），而是**系统性更难**——同样的 agent 配置在 Scene 2 面临更多协同挑战。
- Scene 2 成功 runs 的 token 消耗显著更低（395K vs 967K），可能是因为成功 runs 步数少且 LLM 调用更高效。
- **a5 是唯一在两个场景中都达到 100% 的配置**，这强烈暗示 5 个 agent 时协调架构的负载均衡最优，避免了单点瓶颈。

### 7.2 异常 Token 消耗分析

Scene 1 出现极其异常的 tok/step 值，远高于 Scene 2/3：

| Run | Steps | Total Tokens | Tok/Step | 异常等级 |
|-----|-------|-------------|----------|---------|

**异常原因推测：** 130K-180K tok/step 意味着单步内 LLM 调用了大量 token。可能原因包括：
- Agent 陷入重复规划循环（多轮 LLM 调用/步）
- 上下文窗口积累了过长的历史，导致每步输入膨胀
- LLM 输出格式错误触发重试

相比之下，Scene 2 和 Scene 3 的成功 runs 保持了 13K-23K tok/step 的健康水平。

### 7.3 失败 runs 的 Token 成本

失败 runs 平均消耗约 1.2M-2.6M token，是成功 runs 的 2-3 倍。全部 12 个失败 runs 总计消耗约 **18M token**，按 DeepSeek 定价约 **$9.00**。

## 8. 关键结论与建议

### 8.1 核心发现

1. **agent 数量与成功率呈 U 型曲线** — 2/3/5 agent 表现好，4 agent 表现差（两个场景验证）。这不是简单的"越多越好"问题，而是**协调拓扑**的问题：偶数 agent 可能产生死锁（2v2 对峙），5 agent 有自然多数决机制。

2. **Scene 2 比 Scene 1 难 3.5 倍** — 55% vs 90% 成功率。差异在 agents=2 和 agents=4 最为显著（40% vs 100%, 20% vs 60%）。

3. **agents=5 是唯一在两个场景都达到 100% 的配置** — 这是本次分析最重要的结论。

4. **Scene 1 的 Token 效率问题严重** — 部分 runs 的 tok/step 达到 135K-181K，是正常值的 7-10 倍，需要排查 LLM 调用逻辑。

5. **Scene 3 开局良好** — 早期 8 个 runs 成功率 87.5%，步数表现接近 Scene 1。但还需要更多数据验证。

### 8.2 成本估算

### 8.3 建议

1. **优先分析 agents=4 问题** — 两个场景都表现最差，可能涉及 coordinator 的负载均衡策略。
2. **考虑默认使用 5 agents** — 在所有场景下都表现最佳。
3. **排查 Scene 1 Token 异常** — 部分 runs 的 tok/step 过高，需检查 LLM 调用重试逻辑和上下文管理。
4. **收集更多 Scene 3 数据** — 当前样本量不足以判断 Scene 3 的难度级别。
5. **考虑增加 max_steps** — Scene 2 的 agents=2/3/4 有大量 60 步耗尽失败，若步数放宽到 80-100 可能成败不同。
