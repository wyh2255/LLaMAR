# 人工必要审查点 — 系统健康诊断 agentic 审查者

## 1. 原则

人工只审查不可由自动化/独立 agent 替代的**语义、持久化、LLM 暴露和正式可用边界**；不为每个 Phase 增设人工阻塞。完整证据包、划分依据、顺序和拒绝处理见主方案 §9。

本 feature 与长期记忆 feature 的区别：**诊断会改变决策**（在线闭环），所以审查重心从「事实正确性」转移到「**建议安全性**」——诊断错误不再是记忆污染，而是决策误导。

## 2. 审查点总表

| 审查点 | 对应 Gate | 人工判断 | 不可自动化理由 |
|---|---|---|---|
| R0 | G0 | D1–D10 语义与边界 | 决策事件覆盖范围/诊断权威性是产品语义，无客观真值 |
| R1 | G1 | 决策事件写入路径与幂等；脱敏路径；event 采样（allowlist/provenance 不再涉及，独立审查后撤销） | 决策事件是「协调层行为记录」还是「世界状态断言」的边界需人工确认 |
| R2 | G2 | 防回声室语义；只读工具边界；多轮超时实测结果 | 回声室是语义性风险，测试只能守机制不能守语义 |
| R3 | G3 | 预算档；ACL 复验；TRUNCATED 语义 | 诊断段优先级影响 LLM 决策质量，是产品权衡 |
| R4 | G4 | read 矩阵对比 + smoke + 文档 | 正式可用宣告，同 G4 惯例 |

## 3. 各审查点详情

### R0（G0，2026-08-13 已过）

D1–D10 全部拍板（D1 补 activate_plan_node + update_plan，D2–D10 按建议）；独立审查后修订决策项 A1–A6 全部拍板（A1 追认 G4 边界、A2 独立旋钮 `[diagnosis] inject_enabled`、A3 声明式 update_plan、A4 并存、A5 不加 severity、A6 smoke 3/3）。主方案当前 SHA-256 `9dc21222…`（审查点已插入 §9.1）。

### R1（G1）— 决策事件通道

**审查材料**：P1 产物 + 以下证据：
- `coordinator_decision.*` 事件的真实采样（一次实验 run 的 5-10 条事件 JSON，人工检查：内容为语义决策、无 thinking、无 secret、脱敏生效）
- 事件写入路径证据：append_temporal_event 调用点（与 control.* 同构，无 provenance 变更）、幂等键与 idempotency_ledger claim 的测试
- 收集器前缀 +1 的 diff + 反思窗口含 decision 事件的测试；`diagnosis.audit` 永不进反思窗口的测试

**人工判断**：
1. `coordinator_decision` 是否会被误认为真值通道（H1 精神）——确认它是「协调层自身行为记录」，不是「世界状态断言」
2. 决策事件采样中是否有语义意外（如 dispatch 内容含敏感信息、坐标被误脱敏、activate_plan_node 只记行为不记声明内容是否符合预期）
3. 五种类型覆盖面是否完整（有无其他方向性决策遗漏）

### R2（G2）— 诊断 store + agentic 循环

**审查材料**：P2/P3 产物 + 以下证据：
- 真实模型诊断 smoke（3 次独立运行）的诊断输出样本：人工读 3-5 条诊断，判断「finding 是否站得住、suggestion 是否方向合理、有没有幻觉性纠错」
- 防回声室测试：validator 拒绝诊断引诊断
- 多轮循环实测：max_rounds=3 / diagnosis_sec=90 下的真实轮次分布（平均几轮产出诊断、几轮放弃）
- terminal drain 时序实测（R4 风险验证）

**人工判断**：
1. 诊断样本质量——这是「建议安全性」的核心证据：错误诊断长什么样、置信度是否与质量相关
2. 防回声室语义是否充分（只禁直接引用够不够，间接引用怎么算）
3. 多轮超时与 drain 的实测冲突程度，决定 D8 降级策略是否够用

### R3（G3）— 注入与权威性

**审查材料**：P4 产物 + 以下证据：
- coordinator Context before/after 样本（含 `### System Health` 段，人工看格式与内容密度）
- worker 视图零诊断段（ACL 复验）
- 预算裁剪下 TRUNCATED 语义的测试

**人工判断**：
1. 诊断段在 Context 中的观感：会不会喧宾夺主（coordinator 过度听从诊断 vs 忽略诊断）
2. SECTION_PRIORITY 档位是否合理（诊断高于长期记忆是否合适）
3. 结构性隔离（B6）在代码里的表达是否成立——诊断不进投影 reducer 的守护测试 + `diagnosis.audit` 前缀不与任何事实域/收集器前缀交集（原「reflection 最低优先级让位」表述已随 B6 修订废止）

### R4（G4）— 正式可用

同长期记忆 G4 惯例：read 10-run 矩阵、smoke、文档收口。额外关注：诊断注入前后 cov/tr 对比——**如果诊断显著降低性能，即使机制正确也打回**（这是本 feature 独有的验收维度，记忆 feature 没有）。

## 4. 顺序与拒绝处理

- 顺序：R0（已过）→ P1 → R1 → P2/P3 → R2 → P4 → R3 → P5 → R4
- 每个 Gate 打回区分「契约修订（回主方案，重算 hash）」与「实现缺陷（直接修复）」
- R2 拒绝时不得进入 P4（注入面建立在诊断质量之上）
- 任何涉及 H1 边界的行为都必须停在 R1 或 R3，不得绕过
