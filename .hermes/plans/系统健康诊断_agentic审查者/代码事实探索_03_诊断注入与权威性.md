## 2. 预算与丢弃机制

### 2.1 三个常量的定义与消费

- **`SECTION_PRIORITY`（冻结丢弃顺序）**：`sar_orch/environment_state_provider.py:42-50` —— `task_execution_state → spatial_state → embodied_state → long_term_memory(48) → relevant_events`。注释 46-47 明确顺序冻结为 Task > Spatial > Embodied > **Long-term** > Temporal。
- **`SECTION_WEIGHTS`**：`environment_state_provider.py:51-57` —— task 0.25 / spatial 0.35 / embodied 0.20 / long_term 0.05 / relevant_events 0.15（和 = 1.00）。**全仓搜索确认：除定义处与 `__all__`（1363 行）外无任何消费点** —— 权重是文档性常量，不参与 token 切分。
- **`_SECTION_BUDGET_THRESHOLD`**：`environment_state_provider.py:64-70` —— task=1、spatial=1、embodied=3、**long_term=3（68 行）**、relevant_events=4。注释 61-63 说明：长期段是固定上限段，门槛 3，budget=1/2 丢弃并标 TRUNCATED，budget≥3 保留。

### 2.2 消费逻辑 `_apply_budget`（environment_state_provider.py:409-441）

1. `long_term_dropped` 特判：421-424 —— `"long_term_memory" in sections and token_budget < _SECTION_BUDGET_THRESHOLD.get("long_term_memory", 1)`（即 budget < 3）
2. 骨架 result：425-433 —— 四个业务段初始化为空容器 + freshness + next_cursor + **`TRUNCATED_KEY: token_budget <= 0 or long_term_dropped`（432）**
3. `token_budget <= 0` 提前返回（434-435），只留骨架（scope + freshness + TRUNCATED）
4. 主循环 436-440：**按 SECTION_PRIORITY 顺序**，`token_budget >= _SECTION_BUDGET_THRESHOLD.get(name, 1)` 才放行对应段

**关键事实：预算单位是「整数档位」（threshold），不是 token 数**；实际传入的 token_budget 来自 `src/Agent/router_agent/context.py:990-997`（`max(0, token_limit - 1024)` = 78976，见 §6）。生产预算 78976 ≥ 所有门槛，全段渲染；裁剪只在 `token_budget <= 0` 或低于长期段门槛 3 时发生。

### 2.3 新段放哪一档 / 是否要独立 budget 参数

- 长记忆现状：**threshold=3（environment_state_provider.py:68）、权重 0.05（55 行）、丢弃位置在 embodied 之后 temporal 之前（48 行）**。
- 诊断段建议：与长记忆同档（threshold=3，固定上限摘要、低预算可完全裁剪），或按重要度放更高档（4 = relevant_events 档）；**不需要独立 budget 参数** —— 现机制只有单一整数门槛，无 per-section token 分配。
