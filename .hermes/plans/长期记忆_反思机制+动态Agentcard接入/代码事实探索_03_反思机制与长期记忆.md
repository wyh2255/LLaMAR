## 1. control.* 生命周期事件：产生者、事件类型、control_revision、时间线

### 1.1 产生者与生成位置

- 唯一产生点：`MissionRuntime._record_control_transition_locked()`（`src/a2a/coordinator/mission_runtime.py:1198-1233`），在 `apply_physical_status()` 内对每个**合法**状态转移调用（`mission_runtime.py:573-587`）；非法/重复/未知转移不推进 revision、不写 journal（`mission_runtime.py:556-572`，契约测试 `tests/test_memory_control_journal.py:53-67` 钉死）。
- 状态机：`PhysicalState` 枚举（`mission_runtime.py:39-50`）：`PREPARED / DISPATCHING / ACCEPTED / RUNNING / CANCEL_PENDING / COMPLETED / FAILED / CANCELED`；合法转移表 `_ALLOWED_TRANSITIONS`（`mission_runtime.py:67-85` 起）；终态集合 `_TERMINAL_STATES`（`mission_runtime.py:61-64`）。

### 1.2 control_revision 的生成与递增

- **dispatch 局部单调递增**：`control_revision = self._control_revisions.get(dispatch_id, 0) + 1`（`mission_runtime.py:1214-1215`）；每个 dispatch 独立计数（测试 `test_memory_control_journal.py:43-44`：dispatch_a=2 而 dispatch_b=1）。
- 重启恢复：`seed_control_revisions_from_journal()`（`mission_runtime.py:1282-1290`）从持久化 journal 恢复计数。
- 查询口：`control_revision_of(dispatch_id)`（`mission_runtime.py:1235-1238`）；`ControlPlaneReadPort.control_revision()`/`task_views()` 中把 `control_revision` 暴露给读侧（`sar_orch/environment_state_provider.py:160-191`，`sar_orch/coordinator_state_provider.py` 经 `runtime.control_revision_of` 使用）。

### 1.3 持久化与时间线组织

- 持久化表：`control_transition_journal`（`src/a2a/coordinator/memory/store.py:73-84`），主键 `(context_id, runtime_epoch, dispatch_id, control_revision)`——与 control-state snapshot 原子持久化（temp+fsync+replace，`mission_runtime.py:1210-1212` 注释），崩溃后 `MissionRuntimeManager.recover()` 可恢复（测试 `test_memory_control_journal.py:141-173`）。
- journal 摘要：`journal_sha256 = control_transition_digest(9 个命名字段)`（`contracts.py:302-304, 462-491`）；**原始 result 只留 `result_digest`，绝不含 raw body**（`contracts.py:476`，测试 `test_memory_control_journal.py:70-113`）。
- 进入 canonical Memory 的两条路径（同为 `ingest_control_receipt`，`ingestor.py:476-508` → `_claim_and_append_control`，`ingestor.py:440-472`）：
  - 内部转移：`MemoryLifecycleBridge.enqueue → drain`（`ingestor.py:804-838`），由 `server.py:517-518` 的 `ingestor.set_bridge(bridge)` 接线；
  - callback 转移：`ingestor.callback_bundle()` 收集后随回调 bundle 同事务写入（`ingestor.py:310-331`，`server.py:1463, 1512`）。
  - 重启对账：`MemoryLifecycleBridge.reconcile()`（`ingestor.py:843-854`）+ `MemoryRecovery.reconcile_control_journal`（测试 `test_memory_control_journal.py:175-222`）。
- **canonical 事件类型**：`event_type = f"control.{entry.source}.{entry.state}"`（`ingestor.py:555`），例如 `control.dispatch.DISPATCHING`、`control.callback.ACCEPTED`、`control.watchdog_timeout.CANCEL_PENDING`。实测 `source` 取值有 `dispatch`（`mission_runtime.py:1011, 1056`）、`dispatch_acceptance_failed`（1071）、`dispatch_acceptance_error`（1083）、`activation_acceptance`（1099）、`activation_complete`（1152）、`abort_bounded_wait_expired`（637）、`watchdog_timeout`（`task_watchdog.py:426-428`）等；`state` 为 PhysicalState 值。
- **时间线组织**：每条 canonical Temporal 事件带 `occurred_at=entry.observed_at`（`ingestor.py:556`）+ scope 内单调 `sequence`（`ingestor.py:452`）+ `dispatch_id` + `causation_id=f"control:{journal_sha256[:16]}"` + `correlation_id=f"dispatch:{dispatch_id}"`（`ingestor.py:571-572`）——`control_revision` 与 `sequence`/`occurred_at` 构成双重时间线，可作反思输入锚点。
- 幂等：`control_idempotency_key = sha256(["control", scope_id, journal_sha256])`（`ingestor.py:65-66`）；`control_receipt` 表（`store.py:134-141`）防重放，digest 不匹配抛 `ControlReceiptConflictError`（`ingestor.py:146-150, 446-449`）。

### 8.4 Coordinator 决策产物（可作反思锚点）
- **control.* 事件**：天然带 `control_revision` + `observed_at`/`sequence` 时间线（§1）——用户拍板的输入锚点已就绪。
- **LLM 决策循环**：`RouterAgent`（`src/a2a/coordinator/router.py:247` 起，`LLMClient` 构建 :518-560），工具集含 `QueryWorkersTool` + 自定义/额外工具（`send_message`/`query_sar_state`/`query_task_events`/`finish_task`，`sar_orch/coordinator.py:224-269` 的 router step_callback 佐证）；决策动作落到 control 状态转移（dispatch/cancel/finish）后即进 journal。
- **注意（重要缺口）**：LLM 的**决策文本/推理过程本身不进 canonical Memory**——control 事件 payload 只有 `{journal_sha256, result_digest}`（`ingestor.py:565-570`），原始 result 被丢弃。若反思需要"决策内容"（而非仅状态转移），需要一个在线侧记录决策文本的新通道（当前不存在，未在代码中确认任何 LLM 输出进 canonical 的路径）。
- supervision 告警已渲染进 coordinator context（legacy pinned 路径）：`context.py:1416-1424, 1506-1512`（unacknowledged_events/alerts）。

## 9. 现状缺口清单（实现第四类记忆缺什么）

1. **触发时机**：无任何 reflection 钩子；现有一切写入都是逐事件 canonical 事务（`ingestor.py:365-438, 476-508`），无"窗口结束/run 关闭/决策序列完成"聚合点。可选挂点：`MemoryLifecycleBridge`（`ingestor.py:804-838`）、`ingest_control_receipt`、run 关闭 `materialize_compatibility_artifacts`（`server.py:582-639`）、scope close（`ingestor.py:301-303`）。
2. **输入窗口**：无"近期内容"查询——`temporal_events` 只支持全量/after_sequence 增量（`store.py:800-806`）；无按 event_type、按时间窗、按 dispatch/control_revision 范围的过滤；**无跨 scope/跨 run 查询**（scope 强绑定 context_id+epoch 且 closed 不可 reopen，`store.py:46-53` + `tests/test_memory_scope.py:44-55`）。
3. **存储形态**：无第四类 domain/表；`projection_field.domain CHECK IN ('spatial','embodied')`（`store.py:171`）需扩展或新建聚合表；`NormalizedProjectionInputV1.domain` 也只接受两值（`contracts.py:251-252`）。
4. **读侧扩展**：`MemoryReadPort` 无长期记忆方法（`environment_state_provider.py:68-147`）；Context 注入无长期记忆 section（`_SECTION_HEADINGS` 只有 spatial/embodied/relevant_events/task_execution_state/freshness，`environment_state.py:123-129`）；`render_environment_state_view` 需新段；worker 侧 `/environment/state`（`server.py:1987-2004`）与 router `_render_read_port_block`（`context.py:926-977`）同步扩展。
5. **幂等/revision 兼容**：现有幂等键模式（callback/control/supervision/projection，`ingestor.py:43-95`）可复用；但 `bump_revision_in_tx` 是 per-scope 单调（`store.py:785-797`），跨 scope 聚合产物的 revision 语义（canonical/entity/view 三层，§5）需要新定义。
6. **真值隔离**：反思输入必须来自 `ONLINE_PROVENANCE_ALLOWLIST`（`contracts.py:54-64`）且过 `truth_scan_denied` 门（`ingestor.py:108-118`）；control/supervision 已在 allowlist，但**LLM 决策原文不在 canonical**（`ingestor.py:565-570` 只留 digest）——若反思要消费决策内容，需先打通"在线侧决策文本"摄入通道，且该通道必须同样过隔离门；Barrier/真值只能走 §7 的 post-hoc 评估模式。
7. **评估**：`memory_projection_quality.py` 的 `mode=ro` 只读模式（:227）与 post-hoc truth 比较范式（:9-17）可复用；但指标集只有 worker_report_quality / memory_integration_quality（:68-74, 524-534），需新增长期记忆质量指标（如跨 run 一致性、决策模式沉淀准确率、长期记忆新鲜度/冲突率）。
8. **scope 语义**：跨 scope 沉淀 vs 单 scope 的关系未定；closed-scope 栅栏（`ingestor.py:301-303`）意味着"run 结束后才反思"的窗口天然存在（run close 后 scope 已 closed，只读聚合可行，但不能回写原 scope——需要独立聚合命名空间）。
9. **capability/sensor_type 无生产者**（并行待办 2，`长期记忆_反思机制+动态Agentcard接入.md:36-48`）——与长期记忆无直接耦合，但同为"第四类内容来源"缺口。
