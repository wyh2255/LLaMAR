# Memory System Redesign — 实施经验

## 2026-08-06（Phase 3 复核修复）

- **Bundle idempotency 不要放在 temporal_event.idempotency_key 上**：`temporal_event` 有 `UNIQUE(scope_id, idempotency_key)`，同一 projection bundle 的多个 evidence event 若共用 bundle key 会 IntegrityError；不同 bundle 若由不同路径（`ingest_projection` vs `ingest_callback`）携带相同 evidence 也会撞 key。Bundle 去重必须放在 idempotency ledger（同一 BEGIN IMMEDIATE 事务内、evidence insert 之前先 claim），evidence event 的 `idempotency_key` 保持 NULL。
- **Projection 引用 canonical Temporal UUID，evidence id 单独保留**：Temporal 事件与 projection field/relation/outcome 只有共用 minted UUID 才能稳定 join；外部 evidence identity（如 `cb:worker:body_hash:obj:name:step`）放 `evidence_id` 列 + `causation_id`，供审计/幂等。
- **Reducer 同级冲突必须保留当前 holder 的 provenance/event/confidence**：冲突时只更新 outcome 与 `conflict_event_ids`/`conflict_candidates`，绝不用 incoming 覆盖当前值来源，否则 conflict view 会把当前值标记为错来源。
- **idempotency key 需包含 env_step**：相同 evidence_id + 相同 value 但不同 env_step 是新的时序事实，不是重复 bundle；否则乱序测试会误判 `duplicate`。
- **H1-INV-1 的 truth denial 是两道门**：① provenance 必须在 allowlist；② allowlisted provenance 的 value 也可能掩藏 `oracle`/`ground_truth`/direct-world 字段，必须递归 scan 并在 reducer 前 fail-closed；diagnostic 只写通用 reason + digest，绝不回显 raw term/value/secret。
- **验证注意**：`test_environment_state_rename.py::test_excluded_surfaces_are_not_part_of_the_gate` 依赖 `sar_orch/results/`（git-ignored 的 benchmark 运行时产物目录）存在；无该目录时属环境性失败，与代码无关。

## 2026-08-06（Phase 4 H2 准备）

- **共享 HMAC 不能单独认证 worker identity**：若所有 worker 持有同一个 coordinator secret，`HMAC(secret, worker_id)` 只能证明调用方知道共享 secret，不能阻止 worker A 声称为 B。worker-scoped read 必须由服务端持有的 opaque task capability 解析为 `worker_task_id -> active dispatch -> worker_id`，caller 的 viewer/dispatch 只可作为需匹配的候选。
- **shadow compare 必须接入真实 legacy read 生命周期**：只有 diff helper 和单测不能形成 rollout evidence。`shadow` mode 应维持 legacy 为唯一 LLM source，同时针对同 scope/principal 生成 canonical view、逐步比较并将 non-allowlist diff 写入脱敏审计。
- **read-port 失败不能把 UNAVAILABLE 直接混入新旧 view**：受控 rollback 应一次锁存至 legacy，记录脱敏 audit，保留 canonical DB/outbox；后续 Context 始终走旧路径，避免同一轮或后续轮混合两种领域 truth。

## 2026-08-07（Phase 4 H2 shadow 复核）

- **Shadow compare 的两侧必须消费等价的 worker evidence**：跨 worker 的同 step 去重若只发生在 legacy sink，会吞掉 canonical 可见的 C3 conflict；dedup key 必须至少包含 worker/task，单 callback 的 spam dedup 仍保留。
- **不要把 fire cell 合并为 parent 的 current holder**：cell observation 覆盖 parent position/attributes 会破坏 entity identity 和同级冲突语义，导致 legacy 与 canonical 无法比较；parent direct claim 与 cell evidence 必须分别保留。
- **零差异 run 不一定生成 audit 文件**：本实现只在 non-allowlist diff 存在时写 `memory_rollout_audit.ndjson`。运行证据应同时记录 audit 缺失、direct run 参数、DB hash 和 deterministic replay 的 clean counter。
- **跨线程 SQLite 不能只关闭 thread check**：共享 connection 使用 `check_same_thread=False` 后，所有 transaction 外 read 也必须使用同一 `RLock`，否则会与 `BEGIN IMMEDIATE` 交错并触发 sqlite API misuse。
- **human gate 必须绑定实际源码**：运行 metadata 的 HEAD label 不能替代 candidate commit。若 clean evidence 来自未提交工作树，先冻结并重跑，再生成可批准 packet。

## 2026-08-08（H2 worker 启动绑定竞态）

- **`/environment-state` 重试必须每次现签新 proof/nonce**：coordinator 的 nonce store 会把复用 proof 的第二次请求判为 replay，把"瞬态 403"伪装成"真实未授权"并触发 fail-closed latch；有界重试的 payload 构造必须放在循环内。
- **typed 403 只能从 response body 的 `detail` 字段取原因**：FastAPI `HTTPException(detail=...)` 序列化为 `{"detail": "..."}`；按原因分类（瞬态 vs 真实）必须读 response.json()，对裸异常/网络异常做已知 token fallback，命中不到维持 fail-closed。
- **`unknown_worker_task` 对 worker 自己是瞬态、对服务端是 fail-closed**：worker 执行的 task id 一定曾被服务端签发，该 reason 只可能是绑定尚未落盘；worker 端把它列为唯一瞬态条件有界重试，服务端 admission 保持原样，语义不冲突。
- **瞬态 defer 必须与"从未 fetch"区分**：worker 渲染器对任意非 FRESH view 都会 latch；defer 必须用独立 reason（`environment_state_pending_admission`），渲染器据此仅回退 legacy 一次、不 latch。
- **push-callback 注册竞态与 environment-state 是两条独立路径**：`start_work` push 也会早于 `register_worker_task_id` 被拒；push sender 的有界重试须 body 相同、每次新 nonce（idempotency ledger 保证幂等），且只对 `unknown_worker_task` 重试。

## 2026-08-08（Phase 5 兼容性物化）

- **legacy semantic_map.jsonl 的 agent 行有第 4 个顶层 key `object_type`**（非 `object`）：`SemanticMapStore.ingest_observation` 对 agent 走 `_append_jsonl_locked(..., {"object_type": "agent"})`，而 canonical exporter 统一写 `{ts, event_type, observation, object}`；render consumer 只读 `observation`，fixture 校验必须同时接受 `LEGACY_AGENT_TOP_KEYS`。
- **`ts` 类型不统一**：legacy writer 写 float，canonical exporter 写 ISO 字符串；render consumer 不解析 `ts`，兼容消费者不应依赖其类型。
- **ruff 的 `# noqa: BLE001` 在 `except Exception:` + `logger.exception(...)` 时是 unused**：需要 noqa 的是 body 里非日志的 `except Exception`；用 `ruff check --fix` 自动清理最省事。
- **evaluator 的 scope 解析**：`memory_acceptance` 接受 `memory/export_manifest.json` 或 `export_manifest.json` 两种候选；`memory_projection_quality` 硬性要求 `<results_dir>/memory/memory.sqlite3` 存在（只读打开）。experiment run terminal 物化时 export_dir 用 results 根即可命中 `export_manifest.json` 候选。
- **run terminal 物化时机**：experiment 的 poll loop 结束、`a2a_task` 收尾后、进入 `finally` 停 coordinator 之前调用物化；`_resolve_export_scope_id` 优先 active runtime，runtime 已释放时回退 store 最新 revision 的 scope。
- **`--truth-manifest` 是 evaluator-private 边界**：`memory_projection_quality` 需要 frozen 后的 truth manifest/trace，普通 run 不提供就不跑；在 experiment 里作为可选 CLI 参数接线，避免破坏默认 legacy 行为。

## 2026-08-08（Phase 5 renderer 防御与 10-run 模式）

- **Semantic map 中 agent inventory 是 list of strings**（`store.py` 经 `normalize_inventory` 归一化），旧代码/旧投影是 count dict；任何读 inventory 的渲染代码都要兼容 dict 和 list。
- **map_agent `get_fire_info` 的 `regions` 是 list of dicts**（`{"name", "position"}`，来自 `observed_cells` 展开），legacy 观察里是 list of strings；渲染 `regions` 时不要直接 `', '.join(regions)`，逐项判断 dict/str。
- **新增 canonical/归一化投影时，下游纯渲染代码不会自动适配**：改 producer 前先全局搜一遍 `.items()` / `join` 的消费点。
- **10-run 矩阵的正确模式是 `read_port`**：设计 §10.2 的 `--mode semantic` 默认 legacy，但 acceptance 需要 canonical Memory（export manifest/DB）；H2 已批准 `read_port`，H3 需要 canonical 证据，因此矩阵应加 `--memory-read-mode read_port`。

## 2026-08-08（Phase 5 error-code 覆盖）

- **aggregator 的 known set 必须导入完整白名单**，不要复制局部常量：`memory_acceptance.py` 直接从 `Agent.error_taxonomy.FRAMEWORK_ERROR_CODES` 导入并做 `sys.path` 自举（repo ruff 未启用 E402，不要加 `# noqa: E402`，会触发 RUF100）。
- **ToolResult.error 缺省必须是白名单 code**：`result.get("error") or "activation_error"`；barrier 失败用 `result.get("error") or "action_failed"`；不要 `error=str(exc)`（必然成 `unclassified_tool_error`）。
- **`tool_result_from_barrier` 是所有 barrier 型 worker 工具的公共出口**，在它内部统一补 `error` 一处修复覆盖全部工具；同时把 `error` 从 `extra` 排除避免重复 kwargs。
- **MissionRuntime 图激活 codes 由 `activate_plan_node` 透传**，需全部纳入 taxonomy 白名单，否则被 aggregator 计为 unknown。

## 2026-08-08（验收门收尾）

- **凡 `ToolResult(success=False)` 的 error 一律用静态 allowlisted code，detail 放 content**；任何 `error=f"..."`/`error=str(...)` 且前缀不在白名单的都成 `unclassified_tool_error`。排查未知 code 时先读 CSV 的 `ErrorType` 列，再去 coordinator `<task>.ndjson` 的 `tool_result` 事件反查。
- **`httpx.HTTPStatusError.__str__` 不含响应体**：解析 typed 403 必须读 `exc.response.json()['detail']`，失败再扫 `response.text`（proxy 403 可能非 JSON）。
- **跨任务边界的旧 worker_task_id 会解析到已终态 dispatch**：当前 task 尚无成功 fetch 期间，`no_active_dispatch` 应视为瞬态 defer；coordinator 侧对"终态 dispatch 但同 worker 有更新 active dispatch"返回 transient `unknown_worker_task`。
- **PREPARED（从未发送）dispatch 的 cancel 必须幂等本地清理**：否则僵尸 dispatch 阻塞 worker（participant_busy）且 LLM 反复 cancel 循环得到 `task_not_routable_yet`。DISPATCHING（in-flight）用有界等待覆盖注册窗口。
- **区分 race 与 LLM 协议错误**：对已从 MissionGraph 移除、从未派发的节点 id 做 cancel → `unknown_task_id` 是正确的系统信号（prompt 约定勿重试），不应吞并；判断依据是 dispatch 是否有物理记录/是否曾绑定 worker_task_id。

## 2026-08-08（truth recorder）

- **step 约定存在 off-by-one**：barrier 观测 step 是 0-based（自增前 `_step_counter`），而 `drain_step_logs()` 是 1-based；canonical projection 的 `env_step` 用观测 step，truth claim 必须 `step_num - 1`，否则 evaluator 把所有 report 判 stale。
- **`get_env_snapshot()` 部分失真**：expand 只返回 Flammable region（fires 恒空）、Reservoir `.resource_type` 恒 `"?"`（实为 `.type`）、Deposit `.inventory` 恒 `"{}"`（实为 `.storage`）、enum 以 `str()` 输出；需 `controller.field.name_get(name)` 只读补全并跳过占位值。
- **canonical 只接受有 name 的实体**，truth recorder 同样跳过无名对象；Deposit inventory 进不了 canonical（非 agent 的 `inventory` attr 被丢弃），truth 里 per-resource supply count 是 truth-only 覆盖信号，压低 recall 是有意测量。
- **H1 边界**：truth recorder 输出目录必须在 run results dir 之外（sandbox write_roots 含 results dir，agent 可读）；recorder 只读 snapshot/name_get，绝不写 canonical/Context/semantic map。

## 2026-08-09（回调绑定竞态与历史 dispatch）

- **push 必然早于注册**：worker 收到任务立即发 start_work push，coordinator 须等 `send_task_async` 完整 A2A 往返才知 worker_task_id；窗口实测 0.25-0.65s（负载下更长）。只能靠发送端指数退避（约 5s）覆盖，不能提前注册，也不宜 server 端自绑定（共享 HMAC 下有歧义）。判断窗口：对照 control-state journal 的 DISPATCHING→RUNNING 时间与 security_audit 拒绝时间差。
- **rollback 清理的 PREPARED dispatch 不在活跃表也不写 journal**：cancel 这类 id 需用 runtime 分配历史（`_dispatch_history`）兜底，幂等成功；从未存在的 id 才返回 `unknown_task_id`。
- **本机 pytest 需 `-p no:launch_testing -p no:launch_ros`**（ROS 插件缺 lark）；`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 会连 pytest-asyncio 一起禁用，不可用。
